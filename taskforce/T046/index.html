Plano de datos: pull hacia FHIR

Permitir que un consumidor consulte el servicio FHIR de una clínica solo con las consultas que permite su contrato.

Semana 3 · 30 nov – 4 dic 2026Arquitecto/a de espacios de datos2 jornadas2 dependencias · bloquea 5

Objetivo

Permitir que un consumidor consulte el servicio FHIR de una clínica solo con las consultas que permite su contrato.

Hecho cuando: Proxy HTTP con EDR y token temporal que solo deja pasar las consultas del contrato.

Criterios de aceptación

  • Plano de datos HTTP proxy hacia FHIR.
  • Acceso con EDR y token temporal.
  • Consultas fuera del alcance del contrato rechazadas.

Retos tecnológicos

  • Traducir el alcance del contrato a filtros de consulta FHIR.
  • Autenticar el plano de datos ante FHIR con identidad administrada.

Desarrollo

  1. Tipo de dirección de datos HttpData apuntando a FHIR.
  2. Extensión que valida ruta y parámetros contra la oferta.
  3. Identidad administrada con rol FHIR Data Reader.

Integraciones

  • FHIR service (T028), políticas (T086).

Pruebas

  • Consulta permitida devuelve datos; otra ruta devuelve 403.
